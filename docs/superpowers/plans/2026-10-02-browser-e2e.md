# Browser end-to-end tests Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prove in a real Chromium, against the real API and PostgreSQL, six runner/coach scenarios that jsdom cannot show (record, reload, offline, second tab, coach live, revoke).

**Architecture:** A new `tests/e2e` workspace runs Playwright with `workers: 1`. Playwright's `webServer` starts the API (port 3100) and Vite (port 5273) against `running_tracker_test`. Test data is created by an owner-role helper; browser behavior is judged by what the server holds, read through the API.

**Tech Stack:** `@playwright/test` 1.63.0 (exact; Chromium `chromium-1243` is already installed for this version), `pg` 8.23.0 (as in the root), TypeScript 6.0.3, Node 24.

**Spec:** `docs/superpowers/specs/2026-10-02-browser-e2e-design.md`

## Global Constraints

- Exact-pinned dependency versions, no ranges (repository rule); `npm ci` must keep working from the lockfile.
- Workspace script is `e2e`, never `test`; root gets `test:e2e`. `npm run verify` is unchanged and must not start a browser.
- Page origin is exactly `http://127.0.0.1:5273`, API `127.0.0.1:3100`; never `localhost` (Origin is compared exactly).
- API environment: `APP_ENV=test`, `LOCAL_AUTH_ENABLED=true`, `SESSION_COOKIE_SECURE=false`, `ALLOWED_ORIGINS=http://127.0.0.1:5273`, `DATABASE_URL`/`MAINTENANCE_DATABASE_URL` from `TEST_DATABASE_URL`/`TEST_MAINTENANCE_DATABASE_URL`. The owner login for fixtures is `TEST_MIGRATION_DATABASE_URL`; the helper refuses a database whose name does not end in `_test`.
- `workers: 1`, `fullyParallel: false`, `retries: 0`. No fixed sleeps; wait on observable state with explicit timeouts.
- Selectors use roles, labels, `aria-label`s and visible text only; no `data-testid`, no product code change. A product defect found by a scenario is reported and fixed in a separate commit.
- Never touch the `running_tracker` development database or `.env`. `running_tracker_test` is shared with `npm run test:integration`; the two must not run together.
- No secrets, session tokens or GPS payloads in committed files or reports.

## Review Focus

- A leftover run from a failed test blocks the next test (one active run per user): `afterEach` cleanup must run even when the test failed, and the first test must not depend on a clean database — Task 2 pins this.
- Cleanup deleting another test's or the developer's rows: it must delete by the exact IDs it created — Task 2 pins this.
- The suite silently running against the wrong database (an unset or development URL): fail at startup — Task 1 pins this.
- A page signed in as `localhost` or with a stale cookie looks like "Sign in required" and every scenario fails confusingly — Task 1 smoke test asserts "Session ready".
- Reload duplicating or reusing a `seq` — Task 5 pins uniqueness and gap-freeness on the server.
- Offline buffering that "drains" by dropping points — Task 5 asserts exact `seq` sets server-side, not only an empty buffer.
- A second tab that is read-only in the UI but still uploads — Task 6 asserts the server `seq` set, not only the notice.
- A revoked run still visible as "last known" data — Task 7 asserts both the markers and the track selection are empty.
